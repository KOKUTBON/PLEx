How it works

From source to verdict in one static pass.

A conservative pipeline built for CI: deterministic, cacheable, and quiet unless something actually changed.

  1. 01

    Discover

    Include/exclude globs, .gitignore, and changed-only mode scope the files that matter.

  2. 02

    Parse to IR

    Python AST plus a language-agnostic IR; optional JS/TS, Java, Kotlin, and Go parsers.

  3. 03

    Signals & rules

    Loop depth, recursion, and sorts feed complexity hints; rules flag I/O, allocation, and regex risks.

  4. 04

    Score

    Each function gets a risk score, confidence, and severity — tunable per path and per rule.

  5. 05

    Compare

    Head is diffed against the base ref or a stored baseline to surface regressions only.

  6. 06

    Report & gate

    JSON, Markdown, SARIF, HTML, and check runs, with a gate policy that sets the exit code.

Built for pull requests

Review complexity like you review tests.

PLEx compares every changed function with its base version. When find_vip_orders gains a nested loop, the PR gets a sticky comment, a check-run annotation, and a failing gate if your policy says so.

  • Changed-only analysisScan just the files and functions a diff touches.
  • Baselines & budgetsRisk-delta budgets, per-path rules, and strict / balanced / relaxed presets.
  • Native CI surfacesStep summaries, SARIF code scanning, annotations, Slack and Teams payloads.
